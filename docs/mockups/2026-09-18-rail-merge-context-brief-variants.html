Rail 合併後：Product context 同 Agent brief 住邊

2026-09-18 · 參考用，唔係規格。三個變體之間唯一唔同就係嗰兩樣嘢嘅歸屬。 合併本身（議題／主題／收件匣／分類／行動 → 一個「訊號」列表 ＋ 篩選）三個都一樣。

A · 原地不動（最平）

Product context 留喺 Settings ▸ 產品脈絡，唔搬。Agent brief 留喺完整判讀卡（本來就喺卡入面，唔係頁面 chrome）。 失去擁有者嘅只有「整個 Folder Packet 匯出」——收入列表標題嘅 ⋯ 選單。

代價：Product context 冇任何入口提示，編譯失效時你要自己記得入 Settings 睇。齒輪上加一點黃點係唯一提示。

B · 篩選態擁有（中間）

列表頂多一條會隨篩選變嘅脈絡列。揀「可試 / 觀察」時，嗰條列就係現行行動頁嘅擁有權濃縮版： ProductContext 編譯狀態 chip（撳入 Settings）＋ 匯出整個 Folder Packet。Agent brief 照留判讀卡。

代價：多咗一個會變形嘅 surface；篩選一換，同一位置出唔同嘢，要寫清楚規則先唔會變成雜物架。

C · 脈絡頁（最貴，但正面答 F3）

合併五項之後，rail 加返一項「產品脈絡」：可以直接改 ProductContext（唔止 Settings 嘅唯讀預覽）、 擁有 Folder Packet 匯出、亦係 Agent brief 嘅常駐解釋位。Rail 淨變 5 → 2。

代價：加一個 view 同一條路由，one-in-one-out 靠合併嗰四項找數。另外 library 喺 archive mode 已經叫「脈絡」，撞名要處理。

D

訊號

一個列表，五種篩選。撳篩選只係換呢一頁嘅內容，唔會換頁。
